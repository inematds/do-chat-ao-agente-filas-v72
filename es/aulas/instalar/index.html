Clase 4 · 20 min

Instalar inemaccbot hasta que /ping responda

inemaccbot es un gateway de Telegram con cola durable: tú envías el pedido desde el celular y tu computadora (o una VPS) lo ejecuta como agente. En esta clase lo instalas, lo vinculas con tu chat y lo dejas corriendo como servicio.

Empezar la clase

En esta clase vas a

  1. 1Las piezas: Telegram, cola, trabajador, agente
  2. 2Los prerrequisitos y qué se rompe sin cada uno
  3. 3Token, allowlist y el modo emparejamiento
  4. 4Levantarlo a mano y después como servicio

Objetivo: instalar inemaccbot, vincularlo con tu chat y ver cómo /ping responde en Telegram.

01 · Las piezas de inemaccbot

Del celular al resultado.

Haz clic en cada bloque del diagrama para ver qué hace.

02 · La instalación en seis pasos

Probado en Ubuntu con Node 24. El atajo ./scripts/instalar.sh hace la parte mecánica y se detiene en lo que te exige a ti.

1. Prerrequisitos

Node 22 o más reciente (node -v; Ubuntu 24.04 trae el 18). claude instalado y con sesión iniciada: compruébalo con claude auth status; instalado no es lo mismo que autenticado. ffmpeg y python3 para las tareas de audio y video.

Sin claude con sesión iniciada, el bot arranca y acepta comandos, pero todo trabajo de agente falla. Es la falla más confusa, porque todo parece estar bien.

2. Clonar e instalar

Clona el repositorio y ejecuta npm ci (no npm install: el ci sigue el lockfile y la instalación queda igual en todas las máquinas).

Clona también los repos de dominio promoavatar y promoavatar3 como carpetas hermanas. Sin ellos el bot arranca, pero los flujos se rompen en la primera fase y decenas de pruebas fallan.

3. Crear el bot en Telegram

Habla con @BotFather, envía /newbot y guarda el token que te devuelve. Ese valor es el BOT_TOKEN.

El token es un secreto: nunca va a Git, a una captura de pantalla ni a un mensaje.

4. Escribir el .env

Copia el .env.example, protégelo con chmod 600 y completa BOT_TOKEN, QUEUE_DB, STATE_DIR y LOG_FILE.

En ALLOWED_CHAT_IDS, deja 0. Es el modo emparejamiento: el primer /ping registra tu chat como dueño y cierra la puerta. Vacío no es emparejamiento: es un error a propósito, el bot no arranca.

CuidadoMientras la allowlist sea 0, quien envíe /ping primero se queda con el bot. Empareja antes de dejarlo corriendo.

5. Levantarlo y emparejar

Ejecuta npm test y npm run build, y luego levántalo a mano con ./start.sh para ver cualquier error en pantalla.

Envía /ping a tu bot. Él responde con el id del chat y guarda ese id en el .env. A partir de ahí, solo te atiende a ti.

6. Dejarlo como servicio

Para que el bot sobreviva al cierre de sesión y arranque solo al iniciar el sistema, instala el servicio de usuario y activa el linger. En una VPS, usa el servicio de sistema (deploy/inemaccbot-sistema.service).

Nunca ejecutes el ./start.sh y el servicio al mismo tiempo con el mismo token: los dos se disputan los mensajes y cada uno pierde la mitad. El start.sh ya se niega a arrancar cuando el servicio está activo.

03 · Los comandos de la instalación

En orden. Cambia solo lo que se indica.

Terminal · clonar, instalar, probar
cd ~/projetos
git clone https://github.com/inematds/inemaccbot.git
git clone https://github.com/inematds/promoavatar.git
git clone https://github.com/inematds/promoavatar3.git
cd inemaccbot
./scripts/instalar.sh --checar   # solo dice lo que falta, no cambia nada
npm ci
npm test
npm run build
Terminal · .env y primer arranque
cp .env.example .env
chmod 600 .env
# edita el .env: BOT_TOKEN=<del BotFather>  ALLOWED_CHAT_IDS=0
./start.sh       # log en pantalla; Ctrl+C termina drenando lo que esté corriendo
# en Telegram: /ping  →  el bot responde y guarda tu chat id
Terminal · como servicio de usuario
mkdir -p ~/.config/systemd/user
cp deploy/inemaccbot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now inemaccbot
loginctl enable-linger "$USER"
systemctl --user status inemaccbot   # espera: active (running)
Ejemplo del repositorio

En el log aparece la línea de recuperación, incluso con una cola vacía:

boot: recuperação de leases — requeued=0 failed=0

Un error de configuración detiene el proceso en este punto, a propósito. Lee el mensaje antes de tocar cualquier otra cosa.

  • config: falta BOT_TOKEN: el .env no tiene el token.
  • Servicio active pero /ping no responde: allowlist con el id equivocado (el log muestra rejeitada — fora da allowlist).
  • El bot responde, pero todo job falla: claude no tiene la sesión iniciada.
  • tsc: not found en el build: rehazlo con NODE_ENV=development npm ci --include=dev.

El .env del bot guarda configuración: token, allowlist, rutas. Las claves de otros servicios viven en una bóveda aparte, un archivo por máquina con chmod 600, nunca versionado. Regla del proyecto: el .env guarda ruta e id; el secreto de terceros vive en el archivo de su dueño.

04 · Práctica

Reserva una hora sin interrupciones.

E3 · Instalar el inemaccbot

1 h

Sigue los pasos hasta que el bot responda en Telegram. Haz el emparejamiento con ALLOWED_CHAT_IDS=0 y verifica que el .env tenga chmod 600. Después prueba /ajuda y /fila.

Listo cuando: /ping responde en tu Telegram y /fila muestra las colas vacías.

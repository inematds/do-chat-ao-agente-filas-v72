Lesson 2 · 15 min

What goes to the queue (and what stays with you)

Not every task should go to the queue. Before installing anything, you run your list through three questions and get a table: runs on its own, runs with a gate, or stays with you.

Start lesson

In this lesson, you’ll

  1. 1The three triage questions
  2. 2Where a gate makes sense
  3. 3What should not go in the queue
  4. 4Your queue on paper, with ten lines

Goal: Classify ten of your tasks as runs on its own, runs with a gate, or stays with you, and say where each gate goes.

01 · Triaging a task

Three questions, three destinations.

Click each block in the diagram to see what it does.

Click each block. The question that changes the destination most is the third: consequences outside call for a gate.

02 · The three questions, one at a time

With examples of what runs today in inemaccbot.

1. Is the input clear?

The queue doesn't talk with you along the way. The task needs to fit on one line: a link, a file path, or a subject.

inemaccbot skills show the format (the bot's commands stay in Portuguese): transcrever: https://…, explicativo: <subject> | vertical, imagem: a red fox in the snow | ratio=16:9.

Too vague"Give the presentation a little polish." What should be improved, and how much? Keep it with you or turn it into a concrete input.

2. Can you check the result?

In the morning, you'll check the result. If it's a file (text, video, image), you can review it in minutes. If it's "I did several things," there's no way to tell whether it came out right.

In the bot, this is a contract: the agent finishes with RESULT: <path>, and the bot checks that the file exists and has the expected extension.

3. Does it have consequences outside?

Publishing on behalf of the company, sending something to a client, spending paid credits: this is where the gate comes in. The agent prepares it and stops; you approve.

Transcribing a meeting for you to read yourself has no outside consequences. It runs on its own.

In inemaccbotThe /promoavatar writes the copy for each audience and stops. Only after you approve does it move on to the video and reel.

4. Is it okay to start over from scratch?

This question doesn't change whether it goes in the queue; it changes the type. If starting over from scratch is cheap, one skill (one step) is enough. If there's partial work you'd hate to throw away, the right choice is a flow (several phases, with state and resumption).

You'll use both in lessons 5 and 6.

Ask your agent to review the table
Read the fila-no-papel.md file. For each row, check:
1. Does the input fit on one line (link, file, or topic)?
2. Is the result a file or text you can check?
3. Does it have outside consequences (publishing, sending, spending)? If so, is a gate marked?
Point out any rows that should have a different destination and explain why. Don't edit the file.
Simulation: illustrative example
  • Row 4 ("organize the calendar"): vague input. I suggest "stays with you" or rewriting it as "list this week's calendar conflicts."
  • Row 7 ("reply to client emails"): outside consequences without a gate. I suggest "queue with gate": the agent drafts, you send.
  • The others look good.
  • No gates in ten rows: check that nothing is being published or sent.
  • Every row has a gate: you'll spend the morning approving things; see what is for internal use only.
  • Results like "multiple files" or "improve": hard to check.

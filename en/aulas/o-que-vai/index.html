Lesson 2 · 15 min

What goes to the queue (and what stays with you)

Not every task should go to the queue. Before you install anything, you run your list through three questions and come away with a table: runs on its own, runs with a gate, or stays with you.

Start the lesson

In this lesson you will

  1. 1The three triage questions
  2. 2Where a gate makes sense
  3. 3What should not go to the queue
  4. 4Your queue on paper, with ten rows

Goal: sort ten of your tasks into runs on its own, with a gate, or stays with you, and say where each gate goes.

01 · The triage of one task

Three questions, three destinations.

Click each block of the diagram to see what it does.

Tap each block. The question that changes the outcome the most is the third one: a consequence outside calls for a gate.

02 · The three questions, one by one

With examples of what runs today in inemaccbot.

1. Is the input clear?

The queue doesn't chat with you in the middle. The task has to fit on one line: a link, a file path, or a topic.

The inemaccbot skills show the format: transcrever: https://…, explicativo: <assunto> | vertical, imagem: uma raposa ruiva na neve | ratio=16:9.

Too vague"Give the presentation a polish." Improve what, and how far? It stays with you, or it becomes a concrete input.

2. Can you check the result?

In the morning you'll look at the result. If it's a file (text, video, image), you check it in minutes. If it's "I did a bunch of things", there's no way to know whether it came out right.

In the bot, this is a contract: the agent ends with RESULT: <caminho>, and the bot checks that the file exists and has the expected extension.

3. Does it have consequences outside?

Publishing on behalf of the company, sending to a customer, spending paid credit: this is where the gate comes in. The agent prepares and stops; you approve.

Transcribing a meeting for you to read yourself has no consequences outside. It runs on its own.

In inemaccbot/promoavatar writes the texts for each audience and stops. Only after your approval does it move on to the video and the reel.

4. Is redoing it from scratch acceptable?

This question doesn't change whether it goes into the queue; it changes the type. If redoing from scratch is cheap, a single skill (one step) is enough. If there's partial work that would be absurd to throw away, the right choice is a flow (several phases, with state and resume).

You'll use both in lessons 5 and 6.

Request for your agent to review the table
Read the file fila-no-papel.md. For each line, check:
1. Does the input fit on one line (link, file, or subject)?
2. Is the result a file or text that can be checked?
3. Is there an outside consequence (publishing, sending, spending)? If so, is there a gate marked?
Point out the lines that should change destination and say why. Do not change the file.
Simulation: illustrative example
  • Row 4 ("organize the calendar"): vague input. I suggest "stays with you" or rewriting it as "list this week's calendar conflicts".
  • Row 7 ("reply to customer emails"): outside consequence with no gate. I suggest "queue with gate": the agent drafts, you send.
  • The rest are consistent.
  • No gate in ten rows: check that nothing is published or sent.
  • Every row has a gate: you'll spend the morning approving; see what is internal use only.
  • Result "several files" or "improve": hard to check.

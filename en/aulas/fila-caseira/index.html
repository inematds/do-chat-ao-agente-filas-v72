Lesson 3 · 20 min

The homemade queue in 30 lines

Before the bot, you see the whole idea in a short script from the jornada-agentes repository: four folders, one task at a time, resuming after Ctrl+C, and failures kept separate with the reason.

Start the lesson

In this lesson you will

Goal: run the homemade queue, interrupt it midway, and explain why the second run doesn't redo what was already done.

  1. 1/5

    entrada/

    Each .md file is one request, written the way you would write it in the chat. The order is the order of the file names.

  2. 2/5

    rodando/

    The script moves the file here before calling the agent. If you hit Ctrl+C or the computer goes down, it stays here, and that is what makes resuming possible.

  3. 3/5

    feito/

    It worked (code 0 and a non-empty answer): the final file has the request, a --- line, and the agent's answer.

  4. 4/5

    falhou/

    It errored or the answer came back empty: the file goes here with the exit code and whatever the agent printed. The queue moves on to the next one.

  5. 5/5

    Running again only picks up what's left

    At startup, the script puts back into entrada/ whatever was left in rodando/. Whatever is already in feito/ is never redone.

Click each folder. The key trick is rodando/: a task only leaves there when it finishes, going to feito/ or to falhou/.

03 · The script and how to use it

It's in ferramentas/fila-caseira.sh in the jornada-agentes repository. Both engines run through your subscription.

Terminal · prepare and run
git clone https://github.com/inematds/jornada-agentes.git
cd jornada-agentes
mkdir -p fila/entrada
echo "Resuma em 5 linhas o que é uma fila de tarefas." > fila/entrada/01.md
echo "Liste 3 riscos de deixar um agente rodando sozinho." > fila/entrada/02.md
./ferramentas/fila-caseira.sh fila          # default engine: claude
./ferramentas/fila-caseira.sh fila codex    # or codex
The core of fila-caseira.sh (condensed for reading)
mkdir -p "$PASTA/entrada" "$PASTA/rodando" "$PASTA/feito" "$PASTA/falhou"

# resume: whatever was left in "rodando" (crash, Ctrl+C) goes back to the entrada
for f in "$PASTA"/rodando/*.md; do [ -e "$f" ] && mv "$f" "$PASTA/entrada/"; done

for f in "$PASTA"/entrada/*.md; do
  [ -e "$f" ] || { echo "fila vazia"; break; }
  nome=$(basename "$f")
  mv "$f" "$PASTA/rodando/$nome"          # grab the task (only one at a time)
  saida=$(claude -p "$(cat "$PASTA/rodando/$nome")" < /dev/null 2>&1); rc=$?
  if [ $rc -eq 0 ] && [ -n "$saida" ]; then
    # request + --- + answer go to feito/
  else
    # request + ERRO (rc) + output go to falhou/
  fi
done

  1. Creates the four folders (running it again breaks nothing).
  2. Moves back to entrada/ whatever was left in rodando/.
  3. Takes one file at a time and moves it to rodando/ before calling the agent.
  4. Code 0 and a non-empty answer: feito/. Otherwise: falhou/ with the code.
  5. At the end, it counts how many are in each folder.
  • Receives requests through Telegram, not just through files.
  • Five queues with different limits, and automatic retries.
  • A deadline per task and a notice in the chat when it finishes.
  • An approval gate in the middle of the flows.

The next day: review, measure, and create the new rule

The overnight queue is only worthwhile if the morning is short. Read the report in the chat, check each result against what you expected, note how many were right on the first try, and turn the task that failed most into a new rule.

02 · The morning, step by step

1. Read the report

Read the overnight chat. For each task, you should have a result or a reason for failure. A task with no reply is still running or waiting: check /fila.

/completos lists the flows that finished; /status shows the ones that still need something from you (running or failed).

2. Check each result

Open the file or text and compare it with what you expected. Mark it: right on the first try, right with adjustments, wrong, or failed.

Don't fix anything yet. First look at the whole batch: the pattern in the errors appears when you see them all together.

3. Handle the failures

Read the reason. código 143 means it restarted, not that the agent made an error: /refazer. For an input error (broken link, wrong file), fix the input and send it again.

If the agent got it wrong, doing the same thing again isn’t enough: you need a new rule.

4. Write the rule

A good rule is short, concrete, and testable. It says what to do, not just what to avoid. Add it to the project’s AGENTS.md (step 1) or the skill prompt.

Run the same task again with the rule and compare. If it improved, keep the rule; if not, rewrite it.

ExampleMeeting summaries: start with decisions made and who is responsible, in no more than 8 lines.

Simulation: illustrative example

Right the first time: 7 of 10. Two were right after an adjustment (summaries were too long), and one failed because of a broken link.

New rule: "Meeting summaries: decisions and who is responsible first, no more than 8 lines."

The next night: 9 of 10.

  • Fixing it by hand without writing it down: the same failure comes back tomorrow.
  • Measuring only what failed: what matters is the share that was right the first time.
  • Writing a vague rule ("do better"): there’s no way to check it.
  • Restarting the bot while a task is still running to "clean up."

E6 · The morning review

20 min

Fill in conferencia.md with every task from the night: the result, whether it was right the first time, and what went wrong. Address failures based on their cause.

30 min

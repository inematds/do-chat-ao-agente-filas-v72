The next day: check, measure, and create the new rule

A night of queue is only worth it if the morning is short. You read the report in the chat, check each result against what you expected, note how many came out right on the first try, and turn the task that failed most into a new rule.

02 · The morning, step by step

1. Read the report

Read the night chat. For each task you should have a result or a failure reason. A task with no reply at all is running or waiting: check it in /fila.

/completos lists the flows that finished; /status shows the ones that still need something from you (running or failed).

2. Check each result

Open the file or the text and compare it with what you expected. Mark it: right on the first try, right with tweaks, wrong, or failed.

Don't fix anything yet. First look at the whole batch: the pattern of mistakes shows up when you see them all together.

3. Handle the failures

Read the reason. código 143 was a restart, not an agent error: /refazer. Input error (broken link, wrong file): fix the input and send it again.

If the agent misunderstood, just redoing it the same way isn't enough: that's a case for a new rule.

4. Write the rule

A good rule is short, concrete, and testable: it says what to do, not only what to avoid. It goes into the project's AGENTS.md (step 1) or into the skill prompt.

Run the same task again with the rule and compare. If it got better, the rule stays; if not, rewrite it.

ExampleMeeting summaries: start with the decisions made and who is responsible, in at most 8 lines.

Simulation: illustrative example

Right on the first try: 7 of 10. Two right with adjustments (summaries too long) and one failure from a broken link.

New rule: "Meeting summaries: decisions and owners first, 8 lines at most."

The next night: 9 of 10.

  • Fixing it by hand and not writing it down: the same failure comes back tomorrow.
  • Measuring only what failed: what matters is the share right on the first try.
  • Writing a vague rule ("be better"): there is no way to check it.
  • Restarting the bot while a task is still running to "clean up".

20 min

Fill in conferencia.md with each task from the night: result, whether it came out right on the first try, and what went wrong. Handle the failures by cause.

30 min

Write a rule for the task that failed the most (in AGENTS.md or in the skill's prompt). Run the same task again the next night and compare.

Done when: the rule is written, the task ran again, and you noted whether the result improved.

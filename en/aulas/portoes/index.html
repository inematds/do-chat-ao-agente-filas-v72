Lesson 6 · 18 min

Where the gates go: stop before what matters

A flow is a task in several phases, with state saved in each one. The gate is the phase that ends and stops: the bot shows what it did and waits for you. Approving, correcting, or rejecting is the moment you manage instead of doing the work.

Start the lesson

In this lesson you will

  2. 2How the gate stops and what it shows
  3. 3Approve, reject with a correction, redo, or cancel
  4. 4Rehearse with | sombra before spending

Goal: put the gate in the right place in a flow and decide between approving, rejecting with a correction, or canceling.

  1. 1/5

    Request

    The command creates a numbered flow (A#9) and a list of phases. Each phase has its own state; /status shows phase by phase and audience by audience.

  2. 2/5

    Texts

    The agent writes a text for each audience (young people, women…). It's work you don't want to throw away if a later phase fails: that's why it's a flow, not a skill.

  3. 3/5

    Gate

    The phase ends, the bot sends to the chat what it declared to show, and STOPS. You read, correct, and record the avatars. Only with /pronto (or /aprovar, /ok) does the flow continue.

  4. 4/5

    Video

    After the gate come the expensive phases or the ones with consequences: downloading the avatar video, building the reel, and delivering it to the channel. If one fails, /refazer resumes from it, without redoing the texts.

  5. 5/5

    The rule for where the gate goes

    After what needs your eyes, before what's expensive or public. A gate at the start has nothing to show; a gate at the end comes too late.

Click each block. The gate goes after the work you need to read and before what costs money or goes out to the world.

03 · Decisions at the gate

Each command does something different. Mixing them up costs you work.

1. Approve

/pronto A#9 opens the gate. /aprovar, /aprovado and /ok are synonyms, and A#9, a9 and A9 are the same reference.

Without a reference, /pronto releases the flow when only one is waiting; with several, it lists which ones.

2. Reject with a correction

When the flow declares replies at the gate, you can answer with more than "yes": a single word, like reprova, followed by what to fix. The bot runs the domain command and the phase REOPENS with the new material.

It's the "redo it and show me until I approve". Each flow declares the replies it accepts; /ajuda <fluxo> shows which ones.

3. Redo what failed

/refazer A#9 [audience] picks up from the phase that FAILED, without redoing the earlier ones.

It doesn't work for a phase stopped at the gate: that phase didn't fail, it is waiting for you. For that one, the way out is to approve or reject with a correction.

4. Cancel

/cancelar A#9 stops the whole flow and removes it from /status. It's the last resort: to change one text, you lose all the phases.

To delete the flow's files for good, use /limpar A#9, which only shows what would go until you write confirmar.

/pronto A#9           # approves and continues
/refazer A#9 jovens   # picks up from the phase that failed
/cancelar A#9         # stops the whole flow
/limpar A#9           # shows what it would delete
/limpar A#9 confirmar # really deletes
flow.json · how the domain declares a gate
{ "id": "plano", "kind": "function", "tarefa": "cli.rodar",
  "comando": "bash {{repo}}/musicavideo.sh plano {{input}} --bruto",
  "pausa_apos": true,
  "portao": { "mostrar": ["{{artefato:plano}}"] } }
Example from the repository

The phase declares in portao.mostrar what goes to the chat: text goes in the message, audio and images go as files, video goes as a link (a video that is minutes long goes over Telegram's 50 MB limit).

It runs all the way through without stopping for approval, but it still sends to the chat what each gate would have shown. Use it only when you already trust that flow, and never before publishing something you haven't read.

The project documentation records the risk: approving several flows at once without checking can trigger useless waits (the phase that downloads the avatar waits up to 90 minutes before failing when the video was not recorded). Check before you release.

Lesson 4 · 20 min

Install inemaccbot until /ping responds

inemaccbot is a Telegram gateway with a durable queue: you send the request from your phone and your computer (or a VPS) runs it as an agent. In this lesson you install it, pair the bot with your chat, and leave it running as a service.

Start the lesson

In this lesson you will

  1. 1The pieces: Telegram, queue, worker, agent
  2. 2The prerequisites and what breaks without each one
  3. 3Token, allowlist, and pairing mode
  4. 4Start it by hand, then as a service

Goal: install inemaccbot, pair it with your chat, and see /ping respond in Telegram.

From your phone to the result.

02 · The installation in six steps

Tested on Ubuntu with Node 24. The shortcut ./scripts/instalar.sh does the mechanical part and stops at what needs you.

1. Prerequisites

Node 22 or newer (node -v; Ubuntu 24.04 ships 18). claude installed and logged in: check with claude auth status; installed is not the same as authenticated. ffmpeg and python3 for the audio and video tasks.

Without claude logged in, the bot starts and accepts commands, but every agent job fails. It's the most confusing failure, because everything looks right.

2. Clone and install

Clone the repository and run npm ci (not npm install: ci follows the lockfile, so the install is the same on every machine).

Also clone the domain repos promoavatar and promoavatar3 as sibling folders. Without them the bot starts, but the flows break in the first phase and dozens of tests fail.

3. Create the bot on Telegram

Talk to @BotFather, send /newbot, and save the token it gives back. That value is the BOT_TOKEN.

The token is a secret: it never goes into Git, a screenshot, or a message.

4. Write the .env

Copy the .env.example, protect it with chmod 600, and fill in BOT_TOKEN, QUEUE_DB, STATE_DIR, and LOG_FILE.

In ALLOWED_CHAT_IDS, leave 0. That's pairing mode: the first /ping registers your chat as the owner and closes the door. Empty is not pairing: it's an error on purpose, and the bot won't start.

CarefulWhile the allowlist is 0, whoever sends /ping first takes the bot. Pair before you leave it running.

5. Start it and pair

Run npm test and npm run build, then start it by hand with ./start.sh to see any errors on screen.

Send /ping to your bot. It replies with the chat id and saves that id in the .env. From then on, only you are served.

6. Run it as a service

For the bot to survive logout and start by itself at boot, install the user service and turn on linger. On a VPS, use the system service (deploy/inemaccbot-sistema.service).

Never run ./start.sh and the service at the same time with the same token: the two fight over the messages and each one loses half. start.sh already refuses to start when the service is active.

03 · The installation commands

In order. Change only what is indicated.

Terminal · clone, install, test
cd ~/projetos
git clone https://github.com/inematds/inemaccbot.git
git clone https://github.com/inematds/promoavatar.git
git clone https://github.com/inematds/promoavatar3.git
cd inemaccbot
./scripts/instalar.sh --checar   # only tells you what is missing, changes nothing
npm ci
npm test
npm run build
Terminal · .env and first start
cp .env.example .env
chmod 600 .env
# edit the .env: BOT_TOKEN=<from BotFather>  ALLOWED_CHAT_IDS=0
./start.sh       # log on screen; Ctrl+C stops it, draining whatever is running
# in Telegram: /ping  →  the bot replies and saves your chat id
Terminal · as a user service
mkdir -p ~/.config/systemd/user
cp deploy/inemaccbot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now inemaccbot
loginctl enable-linger "$USER"
systemctl --user status inemaccbot   # expect: active (running)
Example from the repository

The recovery line shows up in the log, even on an empty queue:

boot: recuperação de leases — requeued=0 failed=0

A configuration error takes the process down at this point, on purpose. Read the message before touching anything else.

  • config: falta BOT_TOKEN: the .env has no token.
  • Service active but /ping gets no reply: the allowlist has the wrong id (the log shows rejeitada — fora da allowlist).
  • Bot replies, but every job fails: claude is not logged in.
  • tsc: not found during the build: redo it with NODE_ENV=development npm ci --include=dev.

The bot's .env holds configuration: token, allowlist, paths. Keys for other services live in a separate vault, one file per machine with chmod 600, never versioned. Project rule: the .env holds the path and the id; a third party's secret lives in its owner's file.

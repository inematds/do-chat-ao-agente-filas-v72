Lesson 1 · 12 min

From chat to queue: why keep your tasks

In chat, the agent does one thing at a time, and only while the window is open. A durable queue keeps every request, runs them one at a time, picks up again after a crash, and separates what worked from what failed.

  1. 1/5

    Chat

    In chat, you type, wait, copy, and paste. If you close the window or the computer shuts off, the work in progress is gone. Ten tasks = ten waits with you sitting in front of it.

  2. 2/5

    Durable queue

    The request is saved before it runs. In inemaccbot, the queue is a SQLite database on disk; in the homemade queue, it's one file per task in a folder. Shut down? The task is still there.

  3. 3/5

    Worker

    A worker takes a task, hands it to the agent, and waits. If the process crashes midway, the next time it starts up it recovers what was in flight before accepting new work.

  4. 4/5

    Result

    Each task ends in a clear state: it worked (with the file or text) or it failed (with the reason). That's what you check in the morning.

  5. 5/5

    Why this lets you walk away

    Save before running, one at a time, resume after a crash, and keep done separate from failed: with these four guarantees, turning off the screen doesn't cost you any work.

In inemaccbot the request arrives through Telegram; in the homemade queue from lesson 3, it's a .md file in a folder. The idea is the same.

02 · The four guarantees

What you should expect from any queue, homemade or not.

1. Save before running

The request becomes a record on disk the moment it arrives. It doesn't depend on an open window or on the program's memory.

In inemaccbot, each request becomes a job in a database table. It has a number (j13), a queue, a status, and how many attempts are left.

Everyday signYou send the request from your phone, the computer restarts, and the request is still on the list.

2. One at a time (per queue)

Each worker takes one task, finishes it, and only then takes the next. This prevents two jobs from fighting over the same machine.

In inemaccbot there are five queues with different limits: the rendering queue runs one at a time on purpose, because it uses the graphics card; the network queue accepts ten.

3. Resume after a crash

If the process crashes midway, the task isn't lost or left half-done forever. The next time it starts up, whatever was in progress goes back to the queue.

inemaccbot does this before accepting new work and writes to the log: boot: recuperação de leases — requeued=N failed=M. Requeued is what went back to the queue; failed is what had already used up all its attempts.

4. Keep done separate from failed

A task that hit an error doesn't vanish and doesn't block the queue: it goes to the failures side, with the reason written down, and the queue moves on.

The inemaccbot prompts require the agent to finish with RESULT: <path> or ERRO: <short reason>. That contract is what lets you know, without opening anything, how each task ended.

03 · The states of a task

The names change from one queue to another; the idea is the same.

Homemade queue (folders)
fila/
  entrada/   # requests waiting their turn
  rodando/   # the task the agent is working on right now
  feito/     # request + answer
  falhou/    # request + ERRO and the reason
inemaccbot (job status in the database)
queued    # in the queue, waiting its turn
running   # a worker picked it up and is executing it
done      # finished with a result
failed    # ran out of attempts, with the reason
canceled  # you canceled it (/cancelar)
Example from the repository
  • Homemade queue: when you run it again, whatever is in rodando/ goes back to entrada/.
  • inemaccbot: the worker renews a "lease" on the task while it works. If the lease expires because the process crashed, the task goes back to queued as long as there are attempts left.

In the home-made queue: an empty response or an error code from the agent. In inemaccbot: the agent did not finish with RESULT:, the deadline (timeout) ran out, or the attempts (max_tentativas, 2 to 4 in the catalog skills) were used up.
